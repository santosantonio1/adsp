## Project

Final project of the ADSP course (Aplicações de Processamento Digital de Sinais): read the value shown on a portable multimeter's display from a camera image during calibration, and log it. The problem statement is `spec.pdf` (in Portuguese).

Decisions already made by the group (don't reopen them):
- Python + Ultralytics YOLO. No classic DSP pipeline.
- Two detectors: YOLO 1 finds the numeric reading region (`display`), YOLO 2 detects each character inside that crop (`0`-`9`, `.`, `-`). Characters are sorted left to right to build the number.
- Units and prefixes on the display (V, mV, kΩ, DC, ...) are out of scope (the professor's call).
- The stability rule comes from the spec: if the reading is stable, take two consecutive readings; if it oscillates, record max and min. 4 cycles give 8 readings per calibration point.
- Performance and memory don't matter.
- No per-person split of tasks.

## Environment

Run everything from `tf/` with the project venv (Python 3.12, CUDA torch on an NVIDIA T1000 4 GB):

```
/usr/bin/python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

`ROBOFLOW_API_KEY` is exported in `~/.zshrc`. A non-interactive shell may not load it; wrap the command in `zsh -ic "..."` if the variable is empty.

## Data

```
zsh -ic ".venv/bin/python data/download.py"   # Roboflow Universe -> data/raw/<name>/ (skips existing)
.venv/bin/python data/unify.py                 # data/raw -> data/chars/, data/display/ (rebuilt from scratch)
```

- `data/download.py` holds the selected datasets and their pinned versions. `data/unify.py` holds the per-source class mapping (`TASKS`). Change the mapping there, not in the generated files.
- `unify.py` keeps the original train/valid/test splits and converts polygon labels to boxes. It drops images left with no boxes, because they show digits that weren't annotated. It also drops exact duplicates. Images are hard-linked from `data/raw/`.
- `data/raw/`, `data/chars/` and `data/display/` are git-ignored and regenerated by the two scripts. Each output has a `data.yaml` with an absolute `path`, ready for `yolo train data=data/chars/data.yaml`.
- Known gaps: no dataset has `OL`. The `chars` test split is small (61 images). The `display` class means the reading region, not the whole LCD. Three sources are CC BY 4.0, so cite them in the paper.
